## 3. Architecture

Main's `server/sdk-bridge.ts` (0.2-era but already 0.3-safe): `createClaudeSdkCleanEnv` strips only `CLAUDECODE`/`ANTHROPIC_API_KEY` (L64-67); `createClaudeSdkOptions` sets `settingSources: ['user','project','local']` (L96); `ClaudeSdkBridge` routes known message types and debug-logs-and-ignores unknown ones (L503-505); resume uses top-level `resume` with legacy `sessionId` fallback (L260-270). `server/fresh-agent/model-capability-registry.ts` probes SDK `supportedModels()` through a 10s-abort harness with alias-aware `normalizeFreshAgentModelCapabilityCatalog` (`canon`/`aliases` normalization, `readModelId`, `formatCapabilityDisplayName`) and a 5-min TTL cache; `server/fresh-agent-model-capabilities-router.ts` exposes `GET /api/fresh-agent/model-capabilities/:sessionType` (200 fresh / typed 503 on probe failure). The kilroy runtime (`server/fresh-agent/kilroy-runtime.ts`) reuses `createClaudeSdkOptions` — both claude providers share one options surface. Client: `src/lib/fresh-agent-model-capabilities.ts` fetches capabilities gated on dialog providers (opencode) only today; `src/components/fresh-agent/FreshAgentSettingsButton.tsx` builds static-only `modelOptions` (L83) for the simple-list radio UI and fetches capabilities only for freshopencode (L137-144) into `opencodeCapabilities` (L79).

The upgrade needs zero production changes to the options-construction path (already 0.3-safe) but needs: (a) the dependency bump + lockfile churn acceptance; (b) characterization locks so the silent-passivity assumptions in (0) are pinned by runnable tests; (c) selector wiring so the probed 0.3 catalog (whose `canon` full IDs don't match static alias labels) actually appears for claude providers; (d) an evidence-gated default-model bump.
