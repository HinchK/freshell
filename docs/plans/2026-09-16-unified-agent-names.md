### Explicit constraints
- Plan the whole naming change as one implementation; the earlier two-wave split is superseded.
- Scope naming changes and AI title generation to Claude, Codex, and OpenCode coding-agent sessions in CLI and fresh* modes. Preserve the current naming approach for shells, browsers, document viewers, editors, other non-agent panes, and coding providers outside those three.
- Each coding-agent session has one saved name shared by its pane, sidebar/history entry, associated terminal presentation, and tab when that tab takes its name from the session. Do not offer or maintain separately targetable pane/tab/terminal aliases or independent group names for these sessions.

- Retain a name assigned before the durable provider identity exists and transfer it to that identity; moving/reopening a session retains its name, and switching conversations adopts the new session's name.
- A multi-session tab has no separately stored name: it follows its original pane's session while that pane exists, and tab rename targets that session rather than whichever pane last received activity or focus.
- Consolidate existing conflicting saved names once using reliable explicit-rename recency where available and deterministic precedence otherwise; retain a recovery copy without keeping competing overrides active.
- Make automatic Freshell naming reliable from server-side coding-agent session activity for UI, CLI, and API-created sessions, with an immediate fallback and bounded retries. Complete native title ingestion and supported provider writeback in the same plan.
- Expose Rename only for user-directed naming. Do not add or retain a user-facing Generate a new name action, custom-label controls, or Reset to provider title for these sessions.
- Include meaningful red/green/refactor, integration, and end-to-end verification across all six modes, including lifecycle, identity, concurrency, migration, and non-agent non-regression cases.
- Stop after the plan is finished and reviewed. Do not implement, create a PR, merge, deploy, or restart the live server.

### Accepted tradeoffs and residuals
- Different sessions in a split tab keep their own session names; the tab uses one stable session as its naming source.
- Native-provider interfaces bound how promptly an already-running external CLI can redraw an externally changed name; validate and state concrete limitations without weakening Freshell's shared-name guarantees.

**Goal:** A supported coding-agent conversation has one durable name that every Freshell surface displays and renames consistently, including before provider identity exists and after recovery.

**Architecture:** One server `SessionNames` service serializes name decisions and persists them before publishing an authoritative, revisioned record. Runtimes supply identity, first-user-message activity, and native title observations; React selects the accepted record instead of maintaining aliases, and a tab stores only its naming-source relationship. Migration imports legacy evidence once, while native writeback is a retryable projection of an already saved name.

**Tech Stack:** Existing Rust/Axum/Tokio/Serde services, React/Redux Toolkit/TypeScript/Zod client, existing Claude SDK sidecar, Codex app-server and OpenCode serve APIs, Cargo/Vitest/Playwright testing. No new service, database, distributed coordination, or dependency upgrade is required.

## Decisions and exact cross-task interfaces

### Identity and scope

Create `shared/session-names.ts` and matching Serde types in `crates/freshell-protocol/src/session_names.rs`:

```ts
export type NamedProvider = 'claude' | 'codex' | 'opencode'
export type UnifiedAgentMode = NamedProvider | 'freshclaude' | 'freshcodex' | 'freshopencode'
export type NameSource = 'manual' | 'freshell_ai' | 'provider_ai' | 'first_message' | 'directory'
export type NameIntent = 'user' | 'automatic'
export type SessionNameRef =
  | { kind: 'pending'; id: string }
  | { kind: 'session'; provider: NamedProvider; sessionId: string; storageId: string }
export type TabNameSource = { kind: 'session'; paneId: string } | { kind: 'legacy' }
export interface SessionNameRecord {
  ref: SessionNameRef
  name: string
  source: NameSource
  revision: number
  manualRevision?: number
  renamedAt?: number
}
export interface SessionNameUpdate {
  record: SessionNameRecord
  redirects: Array<{ from: SessionNameRef; to: SessionNameRef }>
  changed: boolean
}
export interface RenameSessionNameRequest {
  target: SessionNameRef
  name: string
  nameIntent?: NameIntent
  ifRevision?: number
}
```

Export corresponding Zod schemas, `isUnifiedAgentMode(mode: string | undefined, sessionType?: string): boolean`, and `sessionNameRefKey(ref: SessionNameRef): string` (JSON encoding a discriminated tuple, never colon-splitting opaque IDs). Rust types use the same names, snake_case fields with camelCase Serde serialization, `NamedProvider` enum, `NameRevision = u64` with a JS-safe integer limit, and identical wire enum strings. Use `manual` consistently, not an additional `user` source.

`storageId` is an opaque server-issued stable identifier for a provider storage root. Implement `resolve_name_identity(provider, session_id, storage_root)` in the server: normalize/canonicalize the existing absolute provider root, store its normalized root in the name document's context map, and assign/reuse a monotonically allocated context ID there. Do not regenerate IDs on restart. Resolve Codex through the selected runtime's effective `CODEX_HOME`/app-server `codexHome` and verified rollout context (`codexDurability.candidate.rolloutPath` when present), not through a host-global UUID assumption. CLI and fresh views of the same provider root/ID must resolve to the same key. Preserve existing resume/ownership checks. Ambiguous or contradictory context returns `409 NAME_IDENTITY_AMBIGUOUS`, not a guessed default. Old `{provider,sessionId}` route input is accepted only when the server can resolve exactly one context. Client names never replace or weaken the existing `SessionRef` restore contract.

`ensure_pending` immediately chooses the existing directory-basename fallback for a usable cwd, otherwise the provider display label, at directory rank; accepted input upgrades it without waiting for Gemini. Every new scoped logical conversation gets a separate `namingHandle` before create; use the existing nanoid facility, persist it with pane content, and have the server admit it as a durable pending name reference. It is independent of `createRequestId`, runtime session ID, tab/pane IDs, terminal ID, and `serverInstanceId`. Creation/recovery retries preserve it; genuine new conversation mints another. A restored pane carries `nameRef` and `namingHandle`, even if persistence strips runtime `sessionId`. Only `initial_materialization` binds a pending name into a durable key. Resume uses the existing durable key; switch/new/fork-to-new use the new key without copying the old name. Explicit internal Claude undo/redo continuation may seed the child's record from the parent once, with source preserved, only through an `internal_continuation` reason; it never aliases two durable keys. Codex mint-new crash recovery is a new conversation for naming, while same-thread sidecar restart is a resume.

### Name acceptance, storage, and publication

`SessionNames` lives in the server, stored at the existing configured Freshell data directory's `session-names.json`. One version-1 document contains `nextRevision`, `nextStorageId`, `contexts`, records, pending redirects, generation state, native-write state, and migration receipts. Map keys use the encoded reference. No separate title overrides are authoritative for scoped sessions.

Add the injectable interface in `crates/freshell-freshagent/src/naming.rs`; both `freshell-ws` and the server already depend on this crate. Reuse the project's boxed future style, not `async-trait`:

```rust
pub type NameFuture<T> = Pin<Box<dyn Future<Output = Result<T, NameError>> + Send + 'static>>;
pub trait SessionNaming: Send + Sync {
    fn get(&self, refs: Vec<SessionNameRef>) -> NameFuture<Vec<SessionNameUpdate>>;
    fn ensure_pending(&self, input: PendingNameInput) -> NameFuture<SessionNameUpdate>;
    fn bind_pending(&self, input: BindNameInput) -> NameFuture<SessionNameUpdate>;
    fn rename(&self, input: RenameNameInput) -> NameFuture<SessionNameUpdate>;
    fn activity(&self, input: NameActivity) -> NameFuture<SessionNameUpdate>;
    fn observe_native(&self, input: NativeNameObservation) -> NameFuture<SessionNameUpdate>;
}
```

Define these owned input structs in that file. `PendingNameInput {handle:String, provider:NamedProvider, cwd:Option<String>}`; `BindNameInput {pending:SessionNameRef, target:SessionNameRef}`; `RenameNameInput {target:SessionNameRef, name:String, intent:NameIntent, if_revision:Option<u64>}`; `NameActivity {target:SessionNameRef, mode:String, event_id:String, reason:NameActivityReason, first_user_message:Option<String>, cwd:Option<String>}` where reasons are `AcceptedUserMessage`, `IndexUserMessage`, `Opened`, `Resumed`; `NativeNameObservation {target:SessionNameRef, title:String, origin:NativeNameOrigin, event_id:Option<String>}` where origins are `Snapshot`, `ProviderAi`, `ExplicitUser`, `OwnWrite`. `NameError` has `InvalidName`, `NotFound`, `IdentityAmbiguous`, `Conflict`, `Persistence`, `CommitUncertain` with HTTP mappings 400/404/409/409/503/503. The service has internal `offer(&self, target: SessionNameRef, name: String, source: NameSource) -> NameFuture<SessionNameUpdate>` and generation/native completion methods; arbitrary callers cannot assert `freshell_ai` or native `ExplicitUser` through HTTP.

Acceptance rules:

1. Trim surrounding whitespace; reject an empty/control-only name or over 200 Unicode scalar values with a visible 400. Keep manual names as entered otherwise. Reuse existing short AI title normalization/prompt; do not apply that shortness limit to manual names.
2. `manual > freshell_ai > provider_ai > first_message > directory`. An automatic offer only raises rank; equal-rank automatic observations preserve the accepted value. Explicit user rename may change a manual record or promote the same visible automatic text to manual. `renamedAt` and `manualRevision` are assigned by the server only for proven explicit rename; timestamps from activity or layout are not rename recency.
3. Default omitted `nameIntent` to `automatic` on every scoped create/rename route and tool. Automatic agent suggestions are `provider_ai` rank with internal origin `agent_suggestion`; they are not a Freshell generated result and cannot freeze names. Responses always return the actual accepted winner, including an unchanged winner when a suggestion loses.
4. `ifRevision` provides optional compare-and-set for an editor that opened against an existing record. UI uses it; a concurrent change yields a conflict and the accepted record, not an invisible overwrite. UI captures the target at edit start. For initially unbound UI renames it first ensures/reads that pending target. User operations without `ifRevision` serialize by server commit order.
5. Clone document under one async mutex, apply the decision, allocate the revision only if accepted state changes, and persist before swapping the visible read model or emitting a frame. Do not use `SettingsStore::patch_session_override` as a name commit: it currently swallows persistence errors. Use the write/sync/rename/parent-sync discipline of `freshell_ws::tabs_persist::atomic_write_durable`. Distinguish pre-replace failure from post-replace sync failure in a small private name-store writer: pre-replace failure preserves old visible/disk state; post-replace uncertainty fences mutations and returns `CommitUncertain` until re-read plus durable sync resolves the installed generation. Never announce success from an uncertain write. No network call runs under the name mutex.
6. Publish `session.name.updated` carrying `SessionNameUpdate` only after commit. Binding allocates a new revision even when text is unchanged and includes the pending redirect. `get` returns resolved records plus redirects and omits unknown references without failing the known batch members; rename of an unknown reference returns 404. Redirects are only pending→durable; never durable A→durable B. Copy generation/write state once on bind. If an existing durable record competes with pending, use source rank, then higher server manual revision for manual/manual, then existing durable winner for equal automatic ranks; preserve the losing evidence in migration/recovery data.
7. All REST responses, directory rows, terminal inventory, fresh created/materialized/attach snapshots, and registry projections carry `sessionName: SessionNameRecord` or `nameRef` plus a last-known projection. `sessions.changed` remains directory invalidation; its revision never orders names. A terminal title string is a display cache, never an accepted name input.

Expose `POST /api/session-names/read {refs}` → `{names: SessionNameUpdate[]}`, `PATCH /api/session-names` with the request above → `SessionNameUpdate`, and `POST /api/session-names/import` with the Task 7 migration envelope → acknowledged candidate IDs and accepted updates. Chunk client batch reads to 100 references. On ready/reconnect, bootstrap all open and recently closed name references, independent of the current history page. Missing bindings remain pending or show a neutral provider/directory fallback; they never retarget an edit by UI coordinates.

### Stable tab ownership

Add `nameSource?: TabNameSource` to client `Tab`, Rust `TabRow`, UI layout mirror, registry record schema, closed snapshots, machine workspace/recovery inputs. `undefined` exists only until initial content or migration resolves ownership. An initial picker keeps `nameSource` undefined until its first actual content choice; choosing its first scoped agent is original-pane ownership, not a later mixed-tab addition. For a newly scoped original pane set `{kind:'session',paneId}`; for an original shell/browser/editor/other pane set `{kind:'legacy'}`. Adding a later agent to a legacy tab does not change its existing naming behavior.

A session-owned tab's display is its source pane's current canonical name. Focus, activity, split/add, provider preference and tree traversal cannot change the pointer. `swapPanes` swaps payloads at fixed IDs: swap the pointer to the other ID only when the content swap actually occurred. Move/close of the source chooses the first remaining scoped leaf in depth-first left-to-right order once; if none remains, set legacy and use existing non-agent derivation. Source conversation replacement keeps the logical source and reads the new binding. Replacing source content with a non-agent follows the removal rule. New tab from a moved/copied scoped pane uses that pane, without composing a group label. Copies/recovery that remint pane IDs must remap the pointer through the old→new ID map. Tab rename resolves this source, not active pane.

For old tabs without evidence of original identity, choose a deterministic original candidate once: first leaf is scoped → that leaf; first leaf non-agent → preserve legacy unless persisted identity/title evidence unambiguously proves the tab is already session-named, in which case select the matching scoped leaf. Do not infer this from activity/focus or apply a tab title to every session. Ambiguous labels go to recovery, not an invented ownership claim.

### Generation and native metadata policies

Automatic generation is activity-driven. Initial index hydration may install free directory/first-message/provider fallback records, but must not schedule paid titles across history. Consult `SessionMetadataStore` for known fresh session type: a Kilroy-only session never enters this scheduler merely because its provider is Claude. After the initial index snapshot, a newly observed accepted user message makes that session eligible, even with no live PTY/browser. Explicit open/resume may arm an unattempted series if a first user message exists. Fresh WS and REST sends feed the same sink after user input is accepted; do not use raw keystrokes, ANSI, assistant text, or tool output. OpenCode already-named sessions require targeted first-message lookup on eligibility.

Each record stores generation status, series ID, event/message fingerprint, a bounded first-message excerpt (the existing prompt input limit), started-at timestamps, attempts, next-due time and exhaustion time. Preserve the excerpt while retries need it, then remove it after acceptance/exhaustion; after exhaustion a new eligible message can supply a new excerpt. Four global workers maximum; one job per resolved reference. Attempt immediately, retry after 5 seconds then 30 seconds measured from the preceding failure; each request has a 20-second timeout. Empty/invalid answers consume an attempt. Persist the attempt start before contacting Gemini so a crash consumes that attempt. On restart an interrupted attempt becomes failed and continues the remaining series, not a reset. Disabled naming or missing credentials pauses without consuming an attempt; enabling/resolving credentials resumes only an eligible unexhausted series. After three failures, rearm only on a subsequent distinct accepted user message, at least 30 minutes after the last attempt, with at most six request starts in any rolling 24 hours. Index ticks, reconnects, repeated open/resume, provider title changes and restarts cannot rearm an exhausted series. Once a Freshell AI/manual name is accepted, never schedule another series.

Jobs capture target, series ID and input fingerprint. Resolve pending redirects at completion and accept only if that same series is still current and source is below Freshell AI. A fallback revision increase does not invalidate a useful AI answer; manual/accepted-AI changes do. Genuine conversation switch never redirects the old job to the new conversation. Preserve the existing prompt/model/custom-prompt settings in `ai_title.rs`; provider AI names never suppress generation. The old user-facing generate endpoint is removed from scoped controls and, for scoped compatibility requests, can only ensure an already eligible automatic series, never bypass these protections.

Native ingestion preserves provenance. Generic Claude `custom-title`, Codex `thread.name`, and OpenCode title snapshots are not proof of a human action. Keep separate raw native title observations, including Claude `ai-title`, `agent-name` and summary fallback; observe a proven explicit native rename as `ExplicitUser` only at an actual user-directed command boundary (not generic metadata, notification delivery, or file mtime). The managed Codex proxy's successful forwarded native `thread/name/set` operation is such a boundary; Freshell-origin requests are tagged as own writes. Claude custom-title alone and OpenCode `session.updated` alone remain native fallback observations. Do not invent unavailable native intent signals; preserve those observations in recovery metadata and state the provenance limitation in the native smoke receipt. A documented explicit rename event found during native validation must be wired at that event boundary and covered by that provider's adapter test.

Write back accepted manual and Freshell AI names through supported metadata APIs only. Do not write directory/first-message/provider fallback values back merely because they were observed. Persist desired revision and an own-write receipt before sending; serialize/coalesce writes per session. An old acknowledgement cannot mark a newer revision synchronized. Retain own-write title/source/revision receipts across restart, including pending requests, so Claude's SDK-created `custom-title` cannot promote Freshell AI to manual. Generic native snapshots never replace protected names, even when an old own echo arrives out of order. Keep the desired/in-flight receipt and the last confirmed own-write receipt; no general audit/event log is required, since older generic snapshots also cannot assert human intent. Attempt current revision up to three times (immediate/5s/30s, 20s timeout), then wait for a new canonical revision or an actual provider reconnection; at most one three-attempt reconnect series per 30 minutes for that revision. A native observation differing from a protected canonical name causes a bounded current-value read; only confirmed divergence marks writeback unsynchronized. Reassert the current desired revision using the same three-attempt/30-minute budget, not a fresh budget for every event, so delayed stale events cannot create a write loop. Unsupported method/version is a diagnosed unsupported state, not a transcript/database rewrite fallback. Saved Freshell names remain authoritative during native failure.
