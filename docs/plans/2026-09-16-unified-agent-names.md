## Decisions and exact cross-task interfaces

### Identity and scope

Create `shared/session-names.ts` and matching Serde types in `crates/freshell-protocol/src/session_names.rs` with these precise fields:

- `NamedProvider`: `claude | codex | opencode`; `UnifiedAgentMode`: those three plus `freshclaude | freshcodex | freshopencode`; `NameIntent`: `user | automatic`.
- `NameSource`: `manual | legacy_protected | freshell_ai | provider_ai | first_message | directory`. Only migration can assign `legacy_protected`; its historic origin is unknown, not a claim of human authorship.
- `SessionNameRef`: discriminated `pending` with string `id`, or `session` with `provider: NamedProvider` and string `sessionId`. The session variant reuses the existing structured provider/session identity; no new restore identity.
- `TabNameSource`: `session` with string `paneId`, or `legacy`.
- `SessionNameRecord`: `ref: SessionNameRef`, `name: string`, `source: NameSource`, `revision: number`, optional `manualRevision: number`, optional `renamedAt: number`, optional `legacyOrigin: 'unknown'` (required for `legacy_protected`).
- `SessionNameUpdate`: `record: SessionNameRecord`, `documentGeneration: number`, `redirects: Array<{from: SessionNameRef; to: SessionNameRef; revision: number}>`, `changed: boolean`.
- `RenameSessionNameRequest`: `target: SessionNameRef`, `name: string`, optional `nameIntent: NameIntent`, optional `ifRevision: number`.

Task 3 also projects optional `nativeSync` alongside the record in `SessionNameUpdate`: status `pending | synced | unsynced | unsupported`, `desiredRevision: number`, `locationRevision: number`, optional `observedCurrent: boolean` and `reason: string`. It is display/status data, never another name authority or a public native path. Status-only updates use documentGeneration ordering independently of unchanged visible name revision.

Export corresponding Zod schemas, `isUnifiedAgentMode(mode: string | undefined, sessionType?: string): boolean`, and `sessionNameRefKey(ref: SessionNameRef): string` (JSON encoding a discriminated tuple, never colon-splitting opaque IDs). Rust types use the same names, snake_case fields with camelCase Serde serialization, `NamedProvider` enum, `NameRevision = u64` with a JS-safe integer limit, and identical wire enum strings. Use `manual` consistently, not an additional `user` source.

Define server-internal `NativeLocation` and `NativeAcquisition` in `crates/freshell-protocol/src/native_location.rs`, separate from public naming/restore schemas. `NativeLocation` is provider-specific: Claude selected absolute config root, transcript path, project directory key, original transcript cwd and optional effective project-key override; Codex initialized app-server `codexHome`, native thread ID, optional selected rollout path and persistence evidence; OpenCode effective database path, native session ID, original directory and optional owned local endpoint. `NativeAcquisition` carries that location, evidence kind (`IndexedFile`, `SelectedTranscript`, `InitializedRuntime`, `PersistedMetadata`), and persistence state (`Prospective` or `Verified`). The store assigns `locationRevision: u64` whenever verified routing evidence changes; it is independent of the visible name revision and never a public identity namespace. Persist only routing/recovery inputs, never credentials or arbitrary environment dumps.

Retain this evidence before exact-ID, identity-sink, retired-terminal and snapshot handoffs drop it. Use existing duplicate quarantine and restore/durability guards. Supported relocation of the same verified provider/session updates the location and retains its name; competing copies are not admitted as independently named sessions. A missing/contradictory native route remains unsynchronized, with `NAME_IDENTITY_AMBIGUOUS` for ambiguous acquisition/binding, rather than choosing an ambient default or first matching file. A known canonical record remains readable/renameable even if its native location is unavailable. No arbitrary multi-home discovery or generic remote resolver is added. Client payloads retain nameRef/handle; internal location travels only through the server's relevant acquisition/recovery holders.

`ensure_pending` immediately chooses the existing directory-basename fallback for a usable cwd, otherwise the provider display label, at directory rank; accepted input upgrades it without waiting for Gemini. Every new scoped logical conversation gets a separate `namingHandle` before create; use the existing nanoid facility, persist it with pane content and server admission/ledger state before acknowledging creation. It is independent of `createRequestId`, runtime session ID, tab/pane IDs, terminal ID, and `serverInstanceId`. Creation/recovery retries preserve it; deliberate new conversation mints another. A restored pane carries `nameRef` and `namingHandle` even if runtime `sessionId` is stripped.

Bind pending→session only on verified native persistence/materialization using the existing provider durability evidence. In particular, Codex `thread/start` ID/path and same-connection readback are prospective: retain pending nameRef while recording acquired runtime ID and NativeLocation separately. UI/API/terminal/fresh runtime-ID lookups consult the runtime/ledger-to-handle association and resolve that pending name. A supported metadata write may address an acquired live thread before binding, but only verified durable materialization afterward authorizes binding; neither a successful start nor a bare name-set acknowledgement fabricates a resumable SessionRef. Do not force a model turn or mutate a production transcript to materialize a name.

On zero-turn/pre-persistence restart, attempt the existing supported recovery; if it must mint an initial runtime/native thread because the prospective one never persisted, retain the same pending handle/name and replace only acquisition evidence. Its first real durable materialization transfers the pending record and budgets atomically. This rule applies to all six modes, including headless recovery; a missing transient runtime ID cannot discard an admitted name. Established durable conversation recovery that genuinely creates a different thread is a new session/name, while same-thread recovery resumes its existing name. Deliberate new/switch/fork-to-new uses the new target without copying the previous name. Explicit internal Claude undo/redo continuation may seed the child once with source preserved through `InternalContinuation`; it never redirects one durable identity to another.

### Name acceptance, storage, and publication

`SessionNames` lives in the server, stored at the existing configured Freshell data directory's `session-names.json`. One version-1 document contains `documentGeneration`, `nextRevision`, records, pending redirects, internal locations/location revisions, generation state, native-write state, fair-scheduling cursor, and migration receipts. Every persisted mutation advances documentGeneration, including attempts, locations and receipts without visible text changes. Visible record/redirect revisions remain JS-safe monotonically allocated values. Map keys use the encoded reference. No separate title overrides are authoritative for scoped sessions.

Add the injectable interface in `crates/freshell-freshagent/src/naming.rs`; both `freshell-ws` and the server already depend on this crate. Reuse the project's boxed future style, not `async-trait`:

```rust
pub type NameFuture<T> = Pin<Box<dyn Future<Output = Result<T, NameError>> + Send + 'static>>;
pub trait SessionNaming: Send + Sync {
    fn get(&self, refs: Vec<SessionNameRef>) -> NameFuture<Vec<SessionNameUpdate>>;
    fn ensure_pending(&self, input: PendingNameInput) -> NameFuture<SessionNameUpdate>;
    fn bind_pending(&self, input: BindNameInput) -> NameFuture<SessionNameUpdate>;
    fn rename(&self, input: RenameNameInput) -> NameFuture<SessionNameUpdate>;
    fn activity(&self, input: NameActivity) -> NameFuture<SessionNameUpdate>;
    fn observe_native(&self, input: NativeNameObservation) -> NameFuture<SessionNameUpdate>;
}
```

Define these owned input structs in that file. `PendingNameInput {handle:String, provider:NamedProvider, cwd:Option<String>}`; `BindNameInput {pending:SessionNameRef, target:SessionNameRef, acquisition:NativeAcquisition}` (reject Prospective evidence); `RenameNameInput {target:SessionNameRef, name:String, intent:NameIntent, if_revision:Option<u64>}`; `NameActivity {target:SessionNameRef, mode:String, event_id:String, reason:NameActivityReason, first_user_message:Option<String>, cwd:Option<String>}` where reasons are `AcceptedUserMessage`, `IndexUserMessage`, `Opened`, `Resumed`; `NativeNameObservation {target:SessionNameRef, title:String, origin:NativeNameOrigin, location_revision:u64, event_id:Option<String>}` where origins are `Snapshot`, `ProviderAi`, `OwnWrite`. Add `record_acquisition(target: SessionNameRef, acquisition: NativeAcquisition) -> NameFuture<SessionNameUpdate>` to the trait; it retains prospective routing without binding. `NameError` has `InvalidName`, `NotFound`, `IdentityAmbiguous`, `Conflict`, `Persistence`, `CommitUncertain`, `LockUnavailable` with HTTP mappings 400/404/409/409/503/503/503. The service has internal `offer(&self, target: SessionNameRef, name: String, source: NameSource) -> NameFuture<SessionNameUpdate>` and generation/native completion methods; arbitrary callers cannot assert `freshell_ai` or migration protection through HTTP. Old-location observations cannot mark the current location synchronized.

Acceptance rules:

1. Trim surrounding whitespace; reject an empty/control-only name or over 200 Unicode scalar values with a visible 400. Keep manual names as entered otherwise. Reuse existing short AI title normalization/prompt; do not apply that shortness limit to manual names.
2. For new operations, `manual > freshell_ai > provider_ai > first_message > directory`. Migration-only `legacy_protected` preserves an already-protected old label above automatic sources and below a proven manual name, without claiming human origin. An automatic offer only raises rank; equal-rank automatic observations preserve the accepted value. Explicit user rename may change any record or promote the same text to manual. `renamedAt` and `manualRevision` are assigned only to an actual explicit rename, never to an imported unknown-origin flag; trustworthy historical rename time is retained as evidence, never fabricated from activity/layout timestamps.
3. Default omitted `nameIntent` to `automatic` on every scoped create/rename route and tool. Automatic agent suggestions are `provider_ai` rank with internal origin `agent_suggestion`; they are not a Freshell generated result and cannot freeze names. Responses always return the actual accepted winner, including an unchanged winner when a suggestion loses.
4. `ifRevision` provides optional compare-and-set for an editor that opened against an existing record. UI uses it; a concurrent change yields a conflict and the accepted record, not an invisible overwrite. UI captures the target at edit start. For initially unbound UI renames it first ensures/reads that pending target. User operations without `ifRevision` serialize by server commit order.
5. Canonicalize the configured Freshell data directory and use a stable `.session-names.lock` sidecar, opened create/read/write without truncation and never replaced/unlinked. Under local serialization, acquire supported Rust 1.96 `std::fs::File::try_lock` on a fresh private non-inherited handle; retry contention for at most one monotonic second, then return `LockUnavailable`. Other lock errors fail immediately. Under that lock re-read and validate the complete current document, reconcile any newly encountered generation's durability, apply the decision, and durably replace before swapping the read model. All mutations, including initialization, migration, pending bind, work claims/completions and receipts, follow this path. No dirty-cache merge, optional-lock fallback, or provider call under the transaction. The executing blocking IO owner retains its guard until completion even if an outer caller stops waiting.

Reuse the current platform durability contract from `freshell_ws::tabs_persist::atomic_write_durable`: sibling temp, file sync, replacement, Unix parent sync; do not assert extra Windows directory-sync guarantees. Distinguish pre-replace failure (old state intact) from post-replace uncertainty. Every participant, including a fresh process, reconciles installed file/required parent durability under the sidecar before adopting an unfamiliar generation or mutating from it. Failure returns `CommitUncertain`, retains the last established snapshot and publishes no success; it cannot allocate from a stale counter or synthesize an empty document. Equal generation with different content, corrupt data and decreasing generations are errors.
7. Publish `session.name.updated` only after successful commit/adoption, in local generation order. Binding allocates a record/redirect revision even with unchanged text. `get` returns resolved records plus redirects and omits unknown refs; unknown rename is 404. Redirects are only pending→durable. Bind work state once without another queue entry: union persisted attempt identities and consumed counts (cap remaining allowance at zero if combined starts exceed three), keep one unaccepted series deterministically (existing durable series if present), and discard completions for the superseded series. Already dispatched calls cannot be undone. Rank decides name collision; manual/manual uses actual server manual revision, equal automatic ranks favor the durable record, and migration protection compares retained migration evidence. Preserve losing evidence in recovery.
8. `refresh_current() -> NameFuture<Vec<SessionNameUpdate>>` is the common full-document adoption path before all name-dependent reads, overlays, mutations and reconnect snapshots, plus an unconditional two-second task in `main.rs` independent of auto-title settings/index activity. Skip missed ticks; one bounded lock/read per tick, no concurrent scans. Overlay names after unrelated awaits or re-project on generation change. Adoption swaps records/redirects coherently, updates terminal caches and invalidates directory/search through an ordered publisher; stale queued projections cannot overwrite newer state. Recover internal subscription lag by refreshing/diffing the full snapshot. Client folds record and redirect revisions, never arrival time. Idle healthy clients converge after the tick plus lock/IO/publication time; no hard realtime claim during suspension/IO failure.

All REST responses, directory rows, terminal inventory, fresh created/materialized/attach snapshots, and registry projections carry `sessionName: SessionNameRecord` or `nameRef` plus a last-known projection. ### Generation and native metadata policies

Automatic generation is activity-driven. Initial index hydration may install free directory/first-message/provider fallback records, but must not schedule paid titles across history. Consult `SessionMetadataStore` for known fresh session type: a Kilroy-only session never enters this scheduler merely because its provider is Claude. After the initial index snapshot, a newly observed accepted user message makes that session eligible, even with no live PTY/browser. Explicit open/resume may arm an unattempted series if a first user message exists. Fresh WS and REST sends feed the same sink after user input is accepted; do not use raw keystrokes, ANSI, assistant text, or tool output. OpenCode already-named sessions require targeted first-message lookup on eligibility.

Each record has one durable generation series: status, series ID, existing event/message fingerprint, bounded first-message excerpt (existing prompt limit), persisted attempt identities/start times, consumed count, nextDue and exhaustion time. First eligibility is immediately ready; after failure 1 retry becomes due in 30 seconds, after failure 2 in five minutes, each request bounded to 20 seconds. These are eligibility delays, not queue latency guarantees. Empty/invalid answers and interrupted starts consume an attempt; persist start before dispatch. Recover interrupted starts once as failed at recovery time and schedule the remaining delay from that fold. Disabled naming/missing key pauses without consumption, and capability restoration resumes only remaining eligible work. At three consumed starts the series stays exhausted across messages, opens, reconnects, title changes and restarts. No automatic rearm or daily-budget subsystem. Remove the excerpt after acceptance/exhaustion. Manual, legacy-protected and accepted Freshell AI names stop generation; provider titles do not suppress it.

Use a second stable sidecar `.session-names-worker.lock` with the same strict OS primitive. One actual ready background operation across cooperating same-home processes holds it; acquire worker then document, never the reverse. Re-read/select/claim transactionally, release the document lock before external work, and retain worker ownership in the executing task/helper through outcome fold and cleanup. Missing capability consumes no attempt and releases the guard. Retry delays hold neither lock. Ordinary reads/renames acquire only the document lock. Generation and native work share this serial worker, with a persisted alternating class cursor when both classes have ready work; within generation choose earliest nextDue then stable name-reference key; within native prefer ready manual-name projection, then earliest nextDue/reference key. Coalesce native revisions before dispatch; alternating classes keep manual projection traffic from starving generation. Thirty 20-second first attempts can take about ten minutes before overhead; immediate fallback and independently responsive manual commits are the guarantees, not immediate AI completion.

Jobs capture target, series ID and input fingerprint. Resolve pending redirects at completion and accept only if that same series is current and source is below Freshell AI. A fallback revision increase does not invalidate a useful AI answer; manual/legacy-protected/accepted-AI changes do. Genuine conversation switch never redirects the old job to the new conversation. Preserve the existing prompt/model/custom-prompt settings in `ai_title.rs`; provider AI names never suppress generation. Remove the old user-facing generate control. Scoped compatibility calls to its endpoint may only ensure already eligible unattempted work; they cannot reset/rearm the series.

Native ingestion preserves provenance. Claude `custom-title`/`ai-title`/`agent-name`/summary, Codex `thread.name` and every forwarded `thread/name/set`, and OpenCode title snapshots/`session.updated` are automatic observations unless matched to a known own-write receipt. Codex's automatic and human callers send the same public request; direction, timing, authentication and prior emptiness cannot prove intent. Freshell Rename and declared API/CLI/MCP `nameIntent:user` are the authoritative user boundaries. Public native metadata lacks reliable human provenance; do not intercept TUI `/rename`, keystrokes or prompt text. This provenance limitation is separate from native redraw timing. Preserve raw observations/own receipts without promoting them to manual.

Write back accepted manual and Freshell AI names through supported metadata APIs only; preserve migration-protected names canonically without claiming a native manual origin. Directory/first-message/provider fallbacks are not written back. Each eligible desired canonical revision gets a finite native series of at most three cycles: immediately ready, then minimum five seconds after cycle 1 failure, then 30 seconds after cycle 2 failure. A cycle permits one current-target read before any retry/reconciliation, at most one write, and one confirming read afterward: at most three writes and six reads per desired revision, each request bounded to 20 seconds. Charge the cycle/start before dispatch. No location change, reconnect, observation, restart or repeated capability check replenishes these counters. A newly accepted name decision (text/source revision), including a deliberate user rename, can create a new bounded series; equal unchanged requests cannot. Binding allocates a record revision but is not a new name decision: transfer consumed cycles and remaining read allowance, rebase the desired revision, and retain original attempted receipts. Only a current-revision readback within that allowance can establish the bound target as current; an old acknowledgement alone cannot. Initially missing location/capability pauses before consuming a cycle; unsupported/archived/ephemeral/missing results are explicit native failures, with remaining cycles usable only after a genuine capability/lifecycle change establishes a valid route. Exhaustion is final for that revision. After confirmed synchronization, pause unused cycles; a differing current-location native observation or genuine provider/location reacquisition can make the next remaining cycle ready, subject to any already-recorded failure nextDue. Matching observations do not schedule work. These events never replenish counts. A restart-discovered interrupted cycle is consumed once; continue with the next remaining cycle rather than replaying its dispatch/read allowance.

Persist desired name revision, attempted location/locationRevision, title, source and unique own-write receipt before the call. Re-resolve current target/revision before every dispatch; never replay a queued stale value. Classify results as confirmed response, known undelivered, or ambiguous. A normal success requires response plus current readback at the attempted target, and can synchronize only that exact name and location revision. An old acknowledgement cannot synchronize a newer revision or relocated target. Keep attempted and last confirmed own-write receipts across restart, including ambiguous results; late echoes remain automatic and never change protected canonical values.

The actual local operation retains the worker guard until its task finishes or owned helper cleanup has completed. Timeout does not cancel provider mutation. Kill/wait only a dedicated helper owned by this operation when needed, never a shared Codex/OpenCode runtime or conversation. After local execution ends, external ambiguity does not retain the global guard or create a permanent target fence. Use remaining cycles for bounded current readback and, on divergence, a write of the current desired value. A new revision supersedes old queued repair; old uncertain receipts still travel as provenance. Matching readback after ambiguity records `observedCurrent` but remains visibly/logged `unsynced` with the uncertainty reason; it is not proof an older external request cannot write later. Once finite allowance is exhausted, retain incomplete status and stop repair. No cancellation, native linearizability, exactly-once or indefinite retry guarantee is made. Normal supported persistence/readback remains mandatory in Task 8 and is not excused by this failure policy.
